# 基于「GraphRAG + LangChain 多模态大模型」的新能源汽车故障诊断智能问答系统 



## 项目概述

本项目是一套面向新能源汽车故障诊断场景的智能问答与知识管理系统。系统采用前后端分离架构，以维修技术文档、汽车档案和历史维修工单为业务数据基础，通过 Neo4j 构建新能源汽车领域知识图谱，并使用 GraphRAG（图检索增强生成）将关系网络、关键词检索结果和业务记录融合为可追溯证据，再由 LangChain 统一调用文本大模型或视觉大模型生成诊断辅助回答。

系统服务于维修技师、技术人员、管理员和普通用户，覆盖账号认证、文档管理、知识图谱构建、文字与图片问答、检索证据展示、车辆档案、维修记录、模型路由、数据大屏和数据库后台等功能。系统输出用于辅助诊断，不替代制造商维修手册、现场检测结果和具备资质的维修人员判断。

本系统中的 GraphRAG 指当前工程可落地的“业务数据检索 + 多跳图谱检索 + 证据融合 + 大模型生成”流程，不宣称采用微软 GraphRAG 的社区摘要算法。当前系统不使用 BGE、FAISS 或其他向量数据库，而是通过结构化业务数据和知识图谱增强大模型回答。

### 核心创新点

- **多源证据融合**：同时检索技术文档、汽车档案、维修记录和知识图谱，将回答依据统一组织为证据快照。
- **GraphRAG 图增强问答**：从问题中提取故障码、部件和故障现象等关键词，并围绕命中实体执行最多三层的多跳子图检索。
- **LangChain 模型编排**：所有文本、视觉、摘要、标题和三元组增强抽取统一通过 `langchain-openai` 的 `ChatOpenAI` 调用兼容 OpenAI 协议的模型端点。
- **多模态故障分析**：支持 PNG、JPG、JPEG 和 WebP 故障现场图片上传，由视觉模型结合 GraphRAG 证据进行分析。
- **可追溯智能问答**：回答完成后展示关键词、来源文档、汽车档案、维修记录和相关知识图谱，业务记录可点击查看详情。
- **自动化知识构建**：通过规则抽取与可选的大模型增强抽取，从文档中生成经过实体类型、关系白名单和置信度校验的三元组。
- **Neo4j 优先与故障回退**：Neo4j 可用时直接存储和查询图谱；Neo4j 不可用时自动使用 SQLite 三元组回退库，保证演示与故障场景下的可用性。
- **过程透明化**：问答过程展示 LangChain 初始化、实体理解、GraphRAG 检索、证据编排、模型路由、LLM 推理和引用校验等阶段；建图和摘要任务展示进度与文字反馈。
- **真实/演示双模式**：配置模型密钥和 Neo4j 后可运行真实模式；无外部服务时可使用确定性模型和 SQLite 回退完成系统演示与自动测试。
- **安全与权限控制**：支持管理员、普通用户两种角色，使用安全密码哈希、JWT 鉴权、API Key 加密存储、短信验证码限时及一次性消费，并在高压相关回答中强制加入安全边界。

### 应用场景

- **新能源汽车维修单位**：统一管理维修手册、技术资料、车辆档案和历史维修案例，辅助现场故障排查。
- **汽车培训机构**：通过图谱关系和可追溯问答开展三电系统、充电系统和高压安全培训。
- **在线技术支持**：根据车型、故障码、仪表提示和图片快速生成带证据的排查建议。
- **4S 店与充电站**：查询动力电池、驱动电机、车载充电机、高压互锁和热管理相关知识。
- **故障案例研究**：对维修工单、故障类型、解决方案和知识图谱关系进行汇总分析。
- **管理决策与数据展示**：通过数据大屏查看文档、图谱、车型、维修、用户和问答运行态势。
- **车主初步咨询**：提供非拆解、非高压作业范围内的初步判断和就近检修建议；高风险操作必须交由持证人员完成。

```text
│                    Vue 3 + TypeScript 前端                           │
│ 登录认证｜智能问答｜知识图谱｜车辆维修｜数据大屏｜管理后台           │
│                         Port: 5173                                  │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ REST API / SSE
┌──────────────────────────────▼──────────────────────────────────────┐
│                         Flask 后端                                  │
│ JWT 权限｜业务接口｜检索融合｜任务进度｜模型路由｜文件解析与导出      │
│                         Port: 5010                                  │
└───────────────┬──────────────────┬───────────────────┬──────────────┘
                │                  │                   │
        ┌───────▼───────┐  ┌──────▼────────┐  ┌──────▼──────────────┐
        │ SQLite 业务库  │  │ Neo4j 图数据库 │  │ LangChain ChatOpenAI │
        │ 13 张业务表    │  │ 7687 / 7474   │  │ GLM/兼容模型端点     │
        └───────┬───────┘  └──────┬────────┘  └──────┬──────────────┘
                │                  │                   │
                └──────────┬───────┴───────────┬──────┘
                           ▼                   ▼
                    本地相对路径文件存储    文本/视觉模型 API
```

系统的核心问答链路为：问题与图片输入 → 实体和关键词提取 → SQLite 文档及业务记录关键词检索 → Neo4j 多跳子图检索 → 证据排序与融合 → LangChain 模型路由 → LLM/VLM 流式回答 → 证据快照保存与展示。

SQLite 统一维护 `users`、`sms_verifications`、`folders`、`documents`、`vehicle_archives`、`maintenance_records`、`chat_sessions`、`chat_messages`、`qa_feedback`、`graph_triples`、`graph_tasks`、`model_endpoints` 和 `system_metadata` 共 13 张业务表。

### 技术栈详解

#### 前端技术栈

- **Vue 3**：使用 Composition API 构建响应式单页应用。
- **TypeScript**：为页面状态、接口返回和业务组件提供类型约束。
- **Element Plus**：实现表单、表格、对话框、上传、分页、进度条和状态反馈。
- **Vue Router**：负责登录页、用户页和管理员页面的路由组织及角色守卫。
- **Pinia**：维护用户身份、Token 和应用级状态。
- **Vite**：提供本地开发服务器、热更新和生产构建，默认前端端口为 5173。
- **ECharts**：用于知识图谱、数据大屏、趋势图、饼图和横向排名图展示。
- **Axios + Fetch**：Axios 处理常规 REST API，Fetch 读取智能问答 SSE 流。
- **Markdown 格式化展示**：将模型回答和文档摘要中的标题、段落、列表等结构转换为可读界面，避免直接显示 `###`、`**` 等标记。

#### 后端技术栈

- **Flask**：提供 REST API、SSE 流式响应、文件访问和统一错误处理。
- **SQLite**：保存用户、文档、车辆、维修、会话、任务、模型配置等核心业务数据。
- **Flask-CORS**：支持本地前后端分离开发时的跨域访问。
- **PyJWT**：生成和验证登录 Token，实现接口鉴权与角色权限控制。
- **Werkzeug Security**：使用 PBKDF2 安全哈希保存用户密码，不存储密码明文。
- **Cryptography/Fernet**：使用环境主密钥加密模型 API Key，接口只展示是否已配置。
- **Requests**：调用可配置短信服务商接口，实现短信登录和短信重置密码。
- **python-docx**：解析 Word 文档，并将问答记录导出为 DOCX 文件。
- **pdfplumber**：提取 PDF 文档文本。
- **openpyxl**：读取 XLSX 技术资料。
- **进程内任务执行器**：异步执行单文档、目录批量、增量和全量知识图谱构建任务。

#### 算法服务技术栈

- **Neo4j + Neo4j Python Driver**：保存和查询车辆、部件、故障现象、故障码、原因、检测方法、维修方案、工具、安全风险、技术文档、检测参数和厂商等实体关系。
- **LangChain + langchain-openai**：通过 `ChatOpenAI` 统一调用文本和视觉模型，支持自定义模型名、Base URL、API Key、超时和流式输出。
- **GLM API**：默认兼容智谱 `glm-4.7-flash` 文本模型与 `glm-4.6v-flash` 视觉模型，也可在模型管理页面配置其他 OpenAI 兼容端点。
- **规则抽取 + LLM 增强抽取**：规则抽取保证基础覆盖，大模型抽取补充隐含关系，输出统一经过实体和关系白名单校验。
- **多通道检索排序**：根据关键词在文档内容、摘要、车型说明、故障描述、诊断过程和解决方案中计算相关度，并结合图谱多跳关系生成上下文。
- **确定性演示模型**：无外部模型时输出稳定、可测试的汽车领域回答、标题和摘要。

## 核心技术功能

- **问题理解与关键词提取**：识别新能源汽车部件、故障现象、故障码、车型和维修操作等关键词，并过滤无意义停用词。
- **SQLite 业务检索**：从文档、汽车档案和维修工单中召回与问题相关的结构化业务证据；无直接命中时返回少量明确标记的通用参考。
- **GraphRAG 多跳检索**：在知识图谱中定位种子实体，围绕种子实体检索相关节点、边和路径，形成与问题相关的子图。
- **证据融合与上下文构建**：将关键词、文档摘要、车型说明、维修方案和图谱路径组织为结构化提示词，要求模型区分事实、推断和建议。
- **LangChain 模型路由**：按模态、启用状态、是否配置密钥和优先级选择模型；端点异常时记录状态并尝试后续端点。
- **SSE 流式问答**：前端实时接收阶段、文本增量、证据和完成/错误事件，展示 LangChain、GraphRAG 和 LLM 的处理进度。
- **多模态图片问答**：将用户问题、现场图片和检索证据组合为多模态消息，调用视觉模型分析维修操作或故障现场。
- **三元组抽取与校验**：从文档抽取 `<头实体, 关系, 尾实体>`，仅允许预定义的 12 类节点和 13 类关系写入图谱。
- **异步建图任务**：支持单文档、目录全量、目录增量、全局增量和全量重建，任务记录进度、成功数、失败数、状态和错误信息。
- **Neo4j/SQLite 自动切换**：Neo4j 可用时以 Neo4j 为图谱事实源并清理对应 SQLite 回退记录；Neo4j 不可用时写入和读取 SQLite 三元组。
- **文档智能摘要**：通过 LangChain 生成包含适用范围、系统部件、故障依据、诊断流程、维修复测和安全边界的结构化 Markdown 摘要。
- **会话标题生成**：调用文本模型从车型、故障码和核心现象中生成标题，用户可在进度弹窗中修改后保存。
- **安全诊断约束**：涉及动力电池、高压互锁、充电系统和橙色高压部件时，回答必须提示持证作业、下电、等待放电、验电和绝缘防护。

### 用户端功能

- **账号认证**：支持账号密码登录、短信验证码登录、注册、短信重置密码和退出登录；验证码限时有效且只能消费一次。
- **角色访问**：普通用户可访问智能问答、问答历史和个人中心；管理员可访问全部管理功能。
- **智能问答**：支持文字问题、WebP/PNG/JPG/JPEG 图片、多轮会话和 SSE 流式回答。
- **思考过程反馈**：回答生成期间展示 LangChain 初始化、实体理解、GraphRAG 检索、证据编排、模型路由、LLM 推理和引用校验进度。
- **检索依据面板**：回答完成后展示检索焦点、来源文档、相关汽车档案、维修记录及问题相关知识图谱；文档摘要可展开，记录可点击查看详情。
- **会话管理**：支持创建、切换、重命名、删除和清空会话，并可调用 LLM 自动生成可编辑标题。
- **问答历史**：查看历史会话及当时保存的完整证据快照，并可继续问答。
- **导出功能**：将当前问答会话导出为 Word 文档。
- **反馈功能**：可对回答标记“有帮助”或“需改进”。
- **个人中心**：查看和修改昵称、邮箱、手机号和头像，支持修改登录密码。

### 管理端功能

- **控制台**：汇总用户、文档、图谱节点、汽车档案、维修记录和问答会话数量，展示核心工作入口、服务状态和高压安全提醒。
- **数据大屏**：使用深色工业科技风格集中展示六项核心指标、故障类型、动力类型、品牌覆盖、维修状态、图谱节点、图谱关系、14 日业务趋势和位于页面中央的实时知识图谱，共八个 ECharts 图表/关系网络，并支持自动刷新。
- **用户管理**：支持搜索、分页、新增、编辑、启用/禁用、角色设置和删除用户；密码哈希不回显。
- **文档管理**：支持 TXT、MD、PDF、DOCX、XLSX 文档上传、筛选、分页、查看、编辑、下载和删除；上传文件使用相对路径保存。
- **文档目录管理**：以目录树组织文档，支持创建、编辑和级联删除目录；选中目录后可查看统计信息，并批量执行全量或增量建图。
- **摘要与建图反馈**：生成摘要和构建知识图谱时展示进度条、阶段文字和结果状态；摘要标题、段落和列表按 Markdown 结构正确显示。
- **知识图谱管理**：
  - 单文档建图：只处理当前选中文档，并在文档详情区域展示该文档子图。
  - 全量重建：清空并重新处理全部文档。
  - 增量构建：只处理待构建或失败的文档。
  - 任务历史：查看任务类型、文档、实时进度、状态、成功数、失败数和错误信息，支持失败重试。
  - 节点管理：支持节点搜索、新增、编辑和删除。
  - 三元组管理：支持三元组搜索、新增、编辑和删除。
  - Neo4j 入口：在新页面打开 Neo4j Browser 管理界面。
- **知识图谱可视化**：
  - 默认加载 50 个节点，修改节点类型、关系类型或布局后立即应用筛选。
  - 支持节点搜索、关系筛选、力导向/圆形布局、拖拽、缩放、复位和刷新。
  - 图例完整展示全部节点类型；点击节点后在固定高度的右侧面板展示类型、连接数和相邻关系。
- **汽车档案管理**：
  - 管理车辆编号、厂商、品牌、车型、车型代码、动力类型、技术说明、关联手册、状态和真实车辆图片。
  - 支持搜索、筛选、分页、新增、编辑和删除；编辑弹窗可查看、上传和替换图片。
- **维修记录管理**：
  - 管理工单号、关联车辆、故障类型、故障描述、诊断过程、解决方案、维修日期、技师和状态。
  - 支持多张现场图片、关联技术文档、搜索、筛选、分页和完整 CRUD。
- **模型管理**：
  - 维护文本/视觉模型的模态、供应商、展示名称、模型名、Base URL、优先级和启停状态。
  - 支持上移、下移调整同模态模型顺序，并执行端点连通性测试。
  - API Key 使用 Fernet 加密存入 SQLite，前端只显示是否已配置，不回显明文。
- **数据库管理后台**：
  - 展示并维护 SQLite 的 13 张业务表，支持搜索、分页和受控 CRUD。
  - 敏感字段只写，关键表写入需要二次确认，删除受事务、唯一约束和外键约束保护。
  - 表格行高固定，长文本通过省略和悬浮提示查看，避免破坏整体布局。
